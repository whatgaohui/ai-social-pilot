# Git 执行缺失问题 — 经验教训

## 日期: 2026-05-07

## 问题描述

项目运行了 18 次迭代，但核心代码（账号中心重构、内容库、巡检系统等，约 220KB、12 个文件）从未提交到 git。23 个 git 提交中只有 10 个是真正的代码改动。

## 原因分析

1. **工作日志太详细产生了"已完成"错觉** — worklog.md 记录了每次迭代的详细变更，导致认为"已经记录了 = 已经完成"
2. **E2E 自动提交掩盖了代码未提交的事实** — 每轮测试自动 commit 一次，但这些只是更新报告数字，不是真正的代码
3. **没有"提交闸门"** — 迭代完成后直接进入下一个需求，没有检查点强制先提交

## 解决方案

1. 建立"提交闸门"：代码完成后必须先 git commit 才能接受新需求
2. 代码和文档必须在同一个 commit 中，不允许文档单独成为一次提交
3. E2E 测试报告改为累积更新，N 轮合并为 1 次提交

## 防止再发生

- 迭代完成检查清单（`docs/improvement-plan.md` 第五节）
- AGENTS.md 中明确 Git 规范
- PROJECT.md 第 11.3 节已有规范，问题是没执行 → 现在增加了执行闸门
