# ADR-002: 笔记详情批量采集策略

## 状态: 已采纳
## 日期: 2026-05-07
## 背景: 列表页 API (`/user_posted`) 只返回封面图和标题，缺少正文、图片组、视频 URL。用户看到的笔记详情不完整。已有 `scrapeNoteWithBrowser` 可获取详情，但主流程从未调用。

## 决策: 在列表采集后，筛选缺少正文的笔记（content < 10 字符），批量调用 `/api/scrape/note` 补充详情。采用并发限制=3、批次间隔 2-3s、Promise.allSettled 容忍部分失败的策略。新增 `videoUrl` 和 `detailScrapedAt` 字段到 XhsPost 模型。

## 后果:
- **好处**: 笔记数据从仅有封面图升级为包含完整正文、图片组、视频 URL、标签、精确发布时间
- **代价**: 采集时间增加（每条笔记详情约 5-10s），但并发=3 控制了总耗时。对于大量笔记（50+），首次返回列表快速，详情异步补充。
- **风险**: 视频 URL 有防盗链时效性，建议使用时实时获取或定期刷新。
